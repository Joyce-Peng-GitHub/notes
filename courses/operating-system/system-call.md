# 系统调用

## 动机

如果让应用程序直接操作硬件，会导致：

- 系统不稳定：一个程序可破坏其他程序或内核；
- 无隔离：程序可读写任意内存；
- 无法公平调度资源；
- 安全崩溃：恶意程序可控制整台机器。

因此，内核提供一组有限、受控、经过检查的入口，这就是*系统调用（system call）*。用户程序通过系统调用“请求”内核做事，内核负责权限检查、参数验证、资源分配和错误处理。

现代 CPU 通常支持多个特权级，例如 x86 的 Ring 0～Ring 3：

- **用户态**：应用程序运行在此，权限受限，不能执行特权指令，不能直接访问内核地址空间和硬件。
- **内核态**：操作系统内核运行在此，拥有最高权限，可管理 CPU、内存、磁盘、网卡等。

## 系统调用与函数调用的区别

|  维度  |    普通函数调用    |        系统调用         |
| :--: | :----------: | :-----------------: |
| 特权级  | 同一特权级，通常在用户态 |     从用户态切换到内核态      |
| 地址空间 |   同一进程地址空间   |      进入内核地址空间       |
|  开销  |      较小      |   较大，涉及模式切换、上下文保存   |
|  接口  |    库/语言定义    |   内核 ABI，通常与架构相关    |
| 错误处理 |    返回值、异常    |     设置 `errno`      |
| 稳定性  |   可随库版本变化    | Linux 系统调用 ABI 长期稳定 |

## 流程

### 用户态准备

1. 将参数放入寄存器。
2. 执行系统调用指令。

### CPU 切换

3. CPU 从用户态切换到内核态。
4. 保存返回地址、标志寄存器等，跳转到内核预设入口。
5. 内核保存用户寄存器，切换到内核栈。

### 内核处理

6. 内核检查系统调用号是否合法。
7. 通过系统调用表找到对应内核函数。
8. 内核验证参数，例如检查文件描述符是否有效、用户缓冲区是否可访问。
9. 执行实际工作：写入文件、设备或 socket。若需要等待 I/O，可能阻塞并调度其他进程。
10. 将结果放入寄存器。若出错，返回负的 `errno`。

### 返回用户态

11. 内核恢复用户寄存器，执行指令返回用户态。

---

不同 CPU 架构的系统调用约定不同。系统调用号是内核 ABI 的一部分。Linux 通常不会删除旧系统调用，只会新增或标记废弃，以保持二进制兼容。

## 系统调用的分类与常见例子

|  类别   | 代表系统调用                                                          | 作用                    |
| :---: | :-------------------------------------------------------------- | :-------------------- |
| 进程控制  | `fork`、`clone`、`execve`、`exit`、`wait4`、`kill`                   | 创建、执行、终止、等待进程，发送信号    |
| 文件管理  | `openat`、`read`、`write`、`close`、`lseek`、`stat`、`fsync`          | 打开、读写、关闭、定位、获取文件信息、同步 |
| 目录与权限 | `mkdir`、`unlink`、`rename`、`chmod`、`chown`、`chdir`               | 目录操作、删除、重命名、权限修改      |
| 内存管理  | `brk`、`mmap`、`munmap`、`mprotect`、`madvise`                      | 堆扩展、内存映射、权限修改、建议      |
| 进程间通信 | `pipe`、`futex`、`eventfd`、`timerfd`、`signalfd`                   | 管道、锁、事件通知、定时器、信号      |
| 网络通信  | `socket`、`bind`、`listen`、`accept`、`connect`、`sendmsg`、`recvmsg` | 创建 socket、连接、收发数据     |
| 多路复用  | `select`、`poll`、`epoll_create`、`epoll_ctl`、`epoll_wait`         | 同时等待多个 I/O 事件         |
| 时间与信息 | `clock_gettime`、`gettimeofday`、`uname`、`getpid`、`getrlimit`     | 获取时间、系统信息、进程信息、资源限制   |
| 设备控制  | `ioctl`、`read`、`write`、`mmap`                                   | 控制设备、读写设备、映射设备内存      |
| 安全与调试 | `seccomp`、`ptrace`、`setuid`、`capset`、`chroot`                   | 系统调用过滤、调试、权限、隔离       |

这些只是代表。Linux 系统调用总数因架构而异，通常在几百个量级。

## 封装

应用程序通常不直接写汇编指令触发系统调用，而是调用库函数或 API。

```
应用程序
  -> 库函数 / POSIX API / 编程语言运行时
    -> 系统调用包装函数
      -> 系统调用指令
        -> 内核系统调用处理函数
```

POSIX API 是标准接口，系统调用是具体操作系统的内核 ABI。同一 POSIX 函数在不同系统上可能映射到不同系统调用。

## 实现

Linux 中，系统调用实现通常包括：

1. 定义系统调用号：在架构相关文件中分配编号。
2. 定义服务例程。
3. 注册到系统调用表，保存函数指针。
4. 入口处理：CPU 进入内核后，入口代码保存寄存器，查表调用函数。
5. **参数验证**：内核不能信任用户指针，必须使用 `copy_from_user`、`copy_to_user`、`access_ok` 等检查。
6. **权限检查**：检查进程权限、能力、命名空间、文件权限等。
7. **返回结果**：成功返回非负值或 0，失败返回负 `errno`。

关键的安全原则是**用户态传入的指针和参数都不可信**。如果内核直接解引用用户指针，可能导致崩溃或提权漏洞。

## 性能开销

系统调用比普通函数调用昂贵，主要开销来自：

1. 用户态/内核态模式切换。
2. 寄存器保存与恢复。
3. 内核栈切换。
4. 安全缓解机制（是甚么？），如 KPTI、Spectre/Meltdown 缓解。
5. 参数复制与验证。
6. 可能阻塞、调度、缓存和 TLB 影响。

在现代 x86-64 上，一次系统调用可能是几十到几百纳秒，启用 KPTI 等缓解后可能更高。高频系统调用会成为性能瓶颈。
