# 可剥夺调度与不可剥夺调度

## 定义

### 可剥夺调度

一个进程正在 CPU 上运行时，如果出现更高优先级进程就绪、时间片用完、中断唤醒紧急任务等情况，操作系统可以**强制中断**当前进程，把 CPU 分配给另一个进程。被中断的进程从“运行态”回到“就绪态”，以后再次被调度时继续运行。这种调度策略称为*<u>可剥夺/抢占式</u>调度（Preemptive Scheduling）*。

典型算法：

- 时间片轮转 RR。
- 最短剩余时间优先 SRTF。
- 抢占式优先级调度。
- 多级反馈队列。
- 实时调度中的 RM、EDF 等。

### 不可剥夺调度

一个进程一旦获得 CPU，就会一直运行，直到它**主动放弃 CPU**，这种调度策略称为*<u>不可剥夺/非抢占式/协作式</u>调度（Non-preemptive Scheduling）*。

主动放弃通常发生在：

- 进程运行结束。
- 进程请求 I/O 而阻塞。
- 进程等待信号量、锁、事件。
- 进程主动 `sleep` 或 `yield`。
- 进程出错终止。

在纯不可剥夺调度中，即使时钟中断发生，或者更高优先级进程变为就绪，当前进程也不会被强制换下。

典型算法：

- 先来先服务 FCFS。
- 非抢占式最短作业优先 SJF。
- 非抢占式优先级调度。
- 高响应比优先 HRRN。
- 非抢占式实时调度。

### 混合策略

现代通用操作系统通常采用混合策略：

- 用户态进程可抢占，通过时间片和优先级调度。
- 内核关键区可能不可抢占，或使用抢占计数控制。
- 实时内核如 PREEMPT_RT（是甚么？）追求全内核可抢占，以降低实时延迟。

---

可剥夺调度与不可剥夺调度是操作系统 CPU 调度的两种基本方式，他们的核心区别是**正在运行的进程能否被操作系统强制夺走 CPU**。

## 调度触发时机对比

| 场景           | 可剥夺调度 |    不可剥夺调度     |
| :----------- | :---: | :-----------: |
| 时间片用完        | 立即切换  |   不切换，继续运行    |
| 更高优先级进程就绪    | 可立即抢占 |   等当前进程主动让出   |
| 当前进程阻塞 I/O   |  切换   |      切换       |
| 当前进程结束       |  切换   |      切换       |
| 当前进程主动 yield |  切换   |      切换       |
| 中断唤醒新任务      | 可触发抢占 | 通常只设置标志，不立即切换 |

现代操作系统中，常区分“用户态可抢占”和“内核态可抢占”。很多通用 OS 的用户进程是可抢占的，但内核关键区可能不可抢占，以减少同步复杂度。实时内核通常支持全内核可抢占。

## 优缺点

### 可剥夺调度

#### 优点

1. **响应快**：高优先级、交互式、实时任务能及时获得 CPU。
2. **公平性好**：时间片轮转可让多个进程轮流运行，避免一个进程长期霸占 CPU。
3. **适合分时系统和实时系统**：桌面、服务器、硬实时系统通常需要抢占。
4. **防止长任务阻塞系统**：一个死循环或长计算任务不会永久占 CPU。

#### 缺点

1. **上下文切换开销大**：频繁抢占导致保存/恢复寄存器、栈、页表等，缓存和 TLB（是甚么？）可能被污染。
2. **实现复杂**：需要时钟中断、抢占点、内核抢占计数、调度器入口等。
3. **并发同步复杂**：共享数据可能在任意时刻被抢占，必须加锁或禁用抢占。
4. **可能优先级反转**：低优先级进程持有锁时，高优先级进程可能被阻塞。
5. **调度开销可能降低吞吐量**：切换太频繁会浪费 CPU。

### 不可剥夺调度

#### 优点

1. **切换开销小**：只在进程主动放弃 CPU 时切换，上下文切换次数少。
2. **实现简单**：调度器只需在阻塞、退出、`yield` 等位置调用。
3. **单核上共享数据较容易保护**：进程在内核临界区（？）运行时不会被其他进程抢占，但仍需防中断和多核并行。
4. **适合批处理、嵌入式简单系统、短任务可预测场景**。
5. **缓存局部性好**：进程连续运行，缓存命中率可能更高。

#### 缺点

1. **响应差**：高优先级任务可能等待很久。
2. **不公平**：一个长任务可阻塞后面所有任务。
3. **不适合交互式和硬实时系统**：用户会感到卡顿，实时任务可能错过截止期。
4. **调度延迟大**：抢占延迟可能等于当前进程剩余执行时间。
5. **一个错误进程可能霸占 CPU**：若进程不主动让出，系统可能失去控制。

## 性能

|  指标   |     可剥夺调度     |    不可剥夺调度    |
| :---: | :-----------: | :----------: |
| 响应时间  |       短       |     可能很长     |
| 周转时间  | 通常较好，但切换多可能变差 |   批处理中可能较好   |
| 等待时间  |      较公平      |  长任务可能阻塞短任务  |
|  吞吐量  |    切换多时下降     |   切换少时可能较高   |
|  公平性  |       好       |      差       |
|  实时性  |    好，适合硬实时    | 差，除非任务很短且可预测 |
|  开销   |       高       |      低       |
| 实现复杂度 |       高       |      低       |

## 适用场景

### 可剥夺调度

- 分时系统、桌面系统、服务器。
- 交互式应用。
- 硬实时系统。
- 需要快速响应和高优先级保障的场景。
- 多任务公平共享 CPU。

### 不可剥夺调度

- 批处理系统。
- 简单嵌入式系统。
- 上下文切换开销敏感的系统。
- 任务运行时间短且可预测。
- 共享资源多、希望减少抢占复杂度的场景。
