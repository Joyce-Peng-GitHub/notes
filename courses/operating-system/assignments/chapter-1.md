## 1.

> 在一个计算机系统中，有一台输入设备和一台打印机。现有两道程序投入运行，并且程序 A 先于程序 B 开始运行。程序 A 的运行轨迹为：
> 
> 1. 计算 $50\ \mathrm{ms}$。
> 2. 打印 $100\ \mathrm{ms}$。
> 3. 计算 $50\ \mathrm{ms}$。
> 4. 打印 $100\ \mathrm{ms}$。
> 
> 程序 B 的运行轨迹为：
> 
> 1. 计算 $50\ \mathrm{ms}$。
> 2. 输入 $80\ \mathrm{ms}$。
> 3. 计算 $100\ \mathrm{ms}$。
> 
> 试说明：
> 
> (a) 两道程序运行时，CPU有无空闲等待？若有，请给出其等待时间段，并说明原因。
> 
> (b) 程序 A 和 B 有无等待 CPU 的情况？若有，请给出等待时间段，并说明原因。
> 
> (3) 若采用不可剥夺调度策略，不考虑调度和切换时间，则完成两个作业需要的时间最少是多少。请说明原因。

按照不可剥夺调度，不考虑调度和切换时间，执行过程如下：

1. $[0, 50\ \mathrm{ms})$：A 计算。
2. $[50\ \mathrm{ms}, 100\ \mathrm{ms})$：A 等待打印，切换到 B 计算。
3. $[100\ \mathrm{ms}, 150\ \mathrm{ms})$：B 等待输入，A 仍在打印，CPU 空闲。
4. $[150\ \mathrm{ms}, 200\ \mathrm{ms})$：A 打印完成，CPU 切换到 A 计算。
5. $[200\ \mathrm{ms}, 300\ \mathrm{ms})$：A 开始打印，切换到 B 计算。
### (a)

有。$[100\ \mathrm{ms}, 150\ \mathrm{ms})$ 时 A 在打印，B 在输入，因此 CPU 空闲。

### (b)

有。$[180\ \mathrm{ms}, 200\ \mathrm{ms})$ 时间段中，B 已经完成输入，但 CPU 仍被 A 占用，所以 B 只好等待。

### (3)

根据上述过程，完成两作业所需时间最少为 $300\ \mathrm{ms}$。

## 2.

> 微内核与外核的主要区别是什么？它们分别有哪些优势和劣势？微内核的性能一定差吗？瓶颈在哪里？


### 区别

微内核和外核是两种截然不同的设计。

- 微内核将**机制与策略分离**，内核中只保留最基本、最本质的 OS 功能（机制），文件系统等高级抽象（策略性服务）都作为单独的服务器进程形式运行在用户空间。
- 外核采用**资源与抽象分离**，内核只负责安全地分配和保护原始硬件资源，不提供高级抽象，将如何抽象和使用这些资源的权力交给应用，应用调用 LibOS 使用资源，LibOS 在用户态实现对硬件的管理策略。

### 优劣

微内核：

- 优势：
	- 易于扩展、移值。
	- 更可靠、安全。
- 劣势：
	- 频繁的上下文切换和特权级切换等带来的性能开销大。
	- 设计复杂。

外核：

- 优势：
	- OS 不提供抽象，能够在理论上提供最优性能。
	- 应用对计算有更精确的实时控制。
	- LibOS 在用户态更易调试。
- 劣势：
	- 编程复杂度高，需要为每种应用实现一套 LibOS，定制化过多，维护难度增加。
	- 对计算资源的利用效率主要由应用决定。
	- 缺乏统一的系统调用接口，难以兼容现有 POSIX 协议，缺乏跨场景的通用性，应用生态差。

### 微内核的瓶颈

微内核不一定必然比外核慢。例如，应用需要同时使用文件、网络、图形等多种服务时，微内核有统一的服务生态，可以直接通过进程间通信组合；而外核不同 libOS 抽象可能不兼容，跨抽象转换或重复实现会带来额外开销。此时微内核可能更快。

微内核的瓶颈主要在于进程间通信，用户态的应用请求服务时，会先陷入内核，内核再将请求又转发给用户态的服务进程，中间涉及上下文切换、数据拷贝等昂贵的操作。
